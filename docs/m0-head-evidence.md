# M0 bounded history-head adapter

## Contract

`apps/server/pi/history-head.ts` is an explicitly loaded, project-local Pi
extension. It registers `/pi-web-history-head <token>` in the backend-owned
RPC process. The command samples `sessionManager.getSessionId()`,
`getSessionFile()`, `getLeafId()` and `isIdle()` synchronously. It does not read
entries, open files, append transcript records or request inference.

The reply uses `extension_ui_request` / `notify` with the private prefix
`pi-web:history-head:v1:`. Rust owns its shapes in
`apps/server/src/protocol.rs`; TypeScript declarations are generated by ts-rs.
The module imports types only and needs no runtime SDK dependency.

Limits are enforced at the producer:

- Correlation token: 1–64 ASCII letters, digits, underscores or hyphens.
- Session/leaf IDs: at most 1024 decoded UTF-8 bytes each.
- Session path: at most 4096 decoded UTF-8 bytes; nullable when unavailable.
- Entire prefixed notification: at most 8192 UTF-8 bytes, including JSON escaping.
- Errors: fixed codes, without echoed paths, input or exception messages.

Non-RPC invocation rejects before sampling. A configured session path does not
prove the file exists; a current leaf may be only in memory. The reply is an
instantaneous checkpoint, **not a write lock or a history/live synchronization
protocol**. A future backend must validate the reply, correlate its own token,
consume the private notification before ordinary UI notices, authorize the path,
and discard stale asynchronous history work. No browser endpoint or production
runtime consumes it yet. Generated types do not provide these runtime checks.

## Verification

```sh
bun run --cwd apps/web test test/history-head.test.ts
cargo test --locked -p pi-web --test protocol
python3 scripts/test_rpc_probe.py
python3 scripts/m0-head-smoke.py --run
```

The 14 adapter tests cover successful shared-fixture serialization, invalid
correlation tokens before metadata access, field and UTF-8 bounds, JSON escaping
overhead, nullable metadata, active state, sanitized exceptions and RPC-only
execution. Five Rust protocol tests include the private reply fixture, error
variants, invalid shapes and generated-file drift alongside the existing public
fixture tests. The initial adapter test failed against the empty implementation;
the implemented command and all boundary tests now pass.

The native smoke loads Pi-Bolt 1.4.0 (Pi-Bolt 1.0.7) with MCP disabled, first with
only this extension, then with the configured user extensions. It checks command
provenance with `get_commands` before dispatch, preventing an absent slash command
from accidentally becoming a model prompt. On tiny disposable sessions it verifies:

- Session/path identity agrees with `get_state`; leaf agrees with the tiny
  `get_entries` oracle. This aggregate is not used on large history.
- Invalid tokens return bounded errors; repeated head commands leave the file
  hash unchanged and do not start an agent run.
- In the isolated profile, a deliberate Pi-owned thinking-level change changes
  the checkpoint leaf. A Pi-owned `new_session` changes identity and reports the
  fresh, unpersisted session rather than reusing stale context.
- Both profiles exit 0. No `agent_start` or `extension_error` occurs. No provider
  requests are made. Session storage is directed to a temporary directory.

The first native run hit `PermissionError: [Errno 1] Operation not permitted`
when the existing smoke harness signalled an already-reaped empty process group.
A diagnostic found no remaining members. The harness now confirms group absence
before accepting that particular cleanup result; permission denial with live
members still fails. Two no-process regression tests demonstrate RED then GREEN.
The subsequent complete native smoke passed and left no test-owned RPC process.

## Large-history use and remaining gate

`scripts/m0-history-smoke.py` now uses this adapter for both checkpoints and makes
**no `get_entries` or `get_messages` requests**. Four real-Pi-loadable cases pass,
including 32 MiB payload/metadata tokens. Head data is 199–201 JSON bytes in those
fixtures. The head and file identity/size/timestamps remain unchanged across each
controlled idle projection; projection file hashes also match. See
[`m0-history-evidence.md`](m0-history-evidence.md) for memory and retention evidence.

This resolves bounded authoritative-leaf discovery on the tested binary. The
subsequent [handoff/continuation experiments](m0-handoff-evidence.md) complete the
M0 feasibility gate. Production runtime adoption/reconnect and browser disconnect
handling remain M2/M3 obligations. Successful checkpoint sampling alone does not
permit claiming that late history can never erase or duplicate live messages.

A separate read-only reviewer examined the adapter, shared types, fixtures and
head/history clients, and found no substantive evidence-backed issues. The review
was source-only; native execution was parent-run evidence. Later handoff/dialog
scripts and production runtime behavior were outside that independent scope.
